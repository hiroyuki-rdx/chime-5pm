# 運用ナレッジ（KNOWLEDGE BASE）

日々の運用で使うコマンドと、起きたトラブルへの対処をまとめる。
**初回導入は [SETUP.md](SETUP.md)、設定項目の一覧は [SPECIFICATION.md](SPECIFICATION.md) を参照。**

## 1. システム概要（要約）

| 項目 | 内容 |
|---|---|
| 何をするか | 平日 10:00〜16:00 の毎正時に時報、16:57 に閉館放送 |
| どこにあるか | `/home/pi/campus-chime`（Raspberry Pi 3B / Raspberry Pi OS Lite 32bit） |
| どう動くか | `campus_chime.service`（systemd）が常駐プロセスを維持 |
| ログ | `journalctl -u campus_chime.service`（起動時の先頭に、版とコミット `campus-chime 6.1.0 (a1b2c3d)` と、作り置きの音声の件数が出る） |
| 状態・点検 | `python3 campus_chime.py --status`（版・時刻の同期・サービス・直近の放送・次の予定）／`--check`（設置状態）。どちらも鳴らさず、何も書かない（3-6） |
| 更新 | `bash scripts/update.sh`（3-3） |
| 設定 | `/home/pi/campus-chime/config.json`（Git 管理外） |
| ネットワーク依存 | 天気予報のみ（既定で有効。12 時のみ）。切れても時報音・時刻の読み上げ・ひとこと・蛍の光は鳴る |

放送の流れ（時報）:

```
09:59:57  ポ、ポ、ポ、        ← 440Hz 短音 × 3
10:00:00              ポーン  ← 880Hz 長音（ここが正時）
10:00:01  「午前10時をお知らせしたのだ。」
          ひとこと
```

天気予報が入るのは 12 時だけです。12 時は、正午のアナウンスのあとに天気予報が続きます。

```
「正午をお知らせしたのだ。」
大津の天気
気温
ひとこと
```

12 時以外（10・11・13・14・15・16 時）は天気予報が無く、時刻アナウンスの直後に「ひとこと」になります。

## 2. よく使うコマンド

```bash
cd /home/pi/campus-chime

# 状態・点検（どちらも鳴らさず、何も書かない。読み方は 3-6）
python3 campus_chime.py --status           # 版・時刻の同期・サービス・直近の放送・次の予定
python3 campus_chime.py --check            # 設置状態（設定・作り置きの声・音源・書き込み先）
python3 campus_chime.py --version          # 版とコミット

# 更新（放送の時間帯なら、終わるまで待つ。3-3）
bash scripts/update.sh

# ログ
journalctl -u campus_chime.service -f                 # 追尾
journalctl -u campus_chime.service --since today      # 本日分
journalctl -u campus_chime.service -p err --since -7d # 直近 1 週間のエラー（v5.3.0 から有効。それ以前は常に空だった）
journalctl -u campus_chime.service -p warning --since -7d # 警告も見るなら

# 予定
python3 campus_chime.py --schedule
python3 campus_chime.py --schedule 20

# 試し鳴らし
python3 campus_chime.py --test-hourly      # 時報（現在時刻）
python3 campus_chime.py --test-hourly 12   # 12 時の時報
python3 campus_chime.py --test             # 閉館放送
python3 campus_chime.py --test-all         # 両方
python3 campus_chime.py --weather          # 天気予報の読み上げ文を確認（大津の現況）
python3 campus_chime.py --say "正午をお知らせしたのだ。"   # 作り置きのある文言だけ鳴る

# 音を出さずに内容だけ見る
python3 campus_chime.py --test-all --dry-run

# 制御
sudo systemctl status campus_chime.service   # systemd 側の詳細（--status で足りないとき）
sudo systemctl restart campus_chime.service  # 放送の時間帯でないことを確かめてから（--wait-idle。3-6）
sudo systemctl stop campus_chime.service
sudo systemctl start campus_chime.service
```

## 3. 運用作業

> **16:55〜17:02（閉館放送の前後）は、更新・再起動・停止をしないでください。** 放送中にサービスを再起動しても再生は止まらず、蛍の光の途中なら systemd が約 90 秒後に強制終了します（今後の版で改善予定）。待機中の再起動はすぐに効きます。`bash scripts/update.sh` は、放送の時間帯が終わるまで待ってから再起動します（手で再起動するときは、先に `python3 campus_chime.py --wait-idle` を実行します。3-6）。

### 3-1. 設定を変える

```bash
nano /home/pi/campus-chime/config.json
python3 /home/pi/campus-chime/campus_chime.py --check      # 書き間違いの点検（鳴らさない。3-6）
sudo systemctl restart campus_chime.service
python3 /home/pi/campus-chime/campus_chime.py --schedule
```

変更例は [SETUP.md 7 章](SETUP.md#7-設定を変える) を参照。

### 3-2. ひとことを増やす

追加・変更したひとことは、**作り置きの音声が無いので無音**になります（放送本体は止まりません）。
また、常駐プロセスは `assets/quotes.json` を**起動時に 1 回しか読まない**ため、
反映には**再起動が要ります**。

追加・変更は PC 側で行います。

1. PC で `assets/quotes.json` を編集する
2. 音声を作り直す（`docs/SETUP.md` 9 章 B）
3. commit・push する
4. Pi で更新する（`docs/SETUP.md` 9 章 A）

```bash
cd /home/pi/campus-chime
bash scripts/update.sh
```

`update.sh` は再起動まで行います。`--test-hourly` は常駐とは別のプロセスで動くため、再起動を忘れていても確認だけは通ってしまいます。
手で `git pull` したときは、必ず再起動してください。

削除だけなら手順 2（音声の作り直し）は要りません。ただし編集は削除でも PC 側で行い、commit・push してください。
Pi で `assets/quotes.json` を直接編集すると、次の `git pull` が衝突して更新を取り込めなくなります。

JSON の書式を壊すと読み込みに失敗し、内蔵の予備のひとことに切り替わります（放送は止まりません）。

### 3-3. 更新を取り込む

```bash
cd /home/pi/campus-chime
bash scripts/update.sh
```

`pi` ユーザーで、`sudo` を付けずに実行する。`update.sh` は、現在の版の表示と手元の変更の確認、最新版の取り込み（`git pull --ff-only`）、放送の時間帯の待機（`--wait-idle`。最大 360 秒）、`scripts/setup.sh --no-apt`（時報音の生成・設置状態の点検・サービスの再起動）、結果の表示（旧い版 → 新しい版と `--status`）を順に行う。何度実行しても安全で、`config.json` は上書きしない。

手元で Git 管理下のファイルを書き換えている・`git` が状態を読めない・ブランチではなく特定のコミットを見ている・取り込めない、のどれかのときは、**何も変えずに**理由を表示して止まる（対処は `docs/SETUP.md` 9 章 A の表。手元の変更には、ファイルごとに `git restore --source=HEAD --staged --worktree -- <ファイル>` が案内される）。

取り込み（`git pull`）が止まる原因は、`git` の表示から見分けて案内される。ネットワークの断・履歴の食い違いが既定で、権限の問題（`Permission denied` など。以前に `sudo` で `git` を実行して、リポジトリの中に root のファイルが残っている）なら `sudo chown -R pi:pi /home/pi/campus-chime` が、ディスクの問題（`No space left on device`・`Read-only file system`・`Input/output error`・`Disk quota exceeded`。リポジトリのある SD カードがいっぱいか、エラーのあとで読み取り専用に切り替わっている。権限の語句と一緒に出ても、こちらとして案内される）なら、確かめ方として `df -h`（空き容量）と `dmesg | tail -n 30`（ディスクのエラー）が、手元の Git 管理外のファイルが新しい版のファイルと同じ名前（`would be overwritten`）なら、そのファイルを移すか消すよう案内される。権限かディスクの問題で止まったときは取り込みが途中まで進んでいることがあるので、直したあとの次の実行で「手元の変更」として案内が出たら、その表示に従う。

取り込んだあとで止まることもある（放送の時間帯が 360 秒待っても終わらない・`config.json` を読めない・`setup.sh` が失敗した）。このときコードは新しい版になっているが、サービスはまだ再起動されておらず、古い版のまま動き続けている（`setup.sh` が失敗したときは、再起動の前に止まったことが多い）。原因を直して**もう一度 `bash scripts/update.sh` を実行する**と、すでに最新版でも、サービスに反映した版の記録（`cache/deployed_commit`。`setup.sh` が再起動に成功したときに書く）がいまの版と合わないので、続きから反映する。元の版へ戻す手順は表示だけで、実行しない。表示されるのは、コードを更新した回（取り込みのあとで止まった回を含む）だけで、続きから反映する回（コードがすでに最新のとき）には出ない。戻す可能性があるなら、止まった回の表示を控えておく。

終わったら、`--status` の末尾が「気になる点は見つかりませんでした。」であることを確かめ（3-6）、読み上げが**途切れず（無音の文言が無く）**聞こえることを耳で確認する。

```bash
python3 campus_chime.py --test-hourly 12
```

**v6.1.0 より前の版（v6.0.0 以前）から、初めて更新するとき**は、手元にまだ `update.sh` も `--wait-idle` も無い（実行すると `unrecognized arguments` で終了コード 2 になる）。一度だけ、次のとおり手で行う。**16:55〜17:02（閉館放送の前後）を避けて**実行する（この版には放送の時間帯を待つ仕組みが無く、`setup.sh` がサービスを再起動するため）。

```bash
cd /home/pi/campus-chime
git pull
bash scripts/setup.sh --no-apt   # 時報音の生成・点検・サービスの再起動まで行う
```

これで v6.1.0 以降になるので、次の更新からは `bash scripts/update.sh` を使う。

**`update.sh` が途中で止まったときに手で進める**なら、もう一度 `bash scripts/update.sh` を実行するのが簡単で確実（上のとおり、続きから反映する）。手で行うときは、コードはもう新しい版なので `--wait-idle` が使える。放送の時間帯が終わるのを待ってから実行する。

```bash
cd /home/pi/campus-chime
python3 campus_chime.py --wait-idle   # 放送の時間帯なら、終わるまで待つ
bash scripts/setup.sh --no-apt
sudo systemctl restart campus_chime.service   # setup.sh が再起動までするので、念のための 1 行
```

**v6.0.0 へ更新したときは、設定の古い行を消す。** v6.0.0 で廃止した設定（天気の取得先の切り替え、天気かひとことを選ぶ抽選方式）が `config.json` に残っていると、起動時に警告が出る。値は無視されるので放送は止まらないが、`--check` の「設定」に警告で出る行（「直し方: この行を消してください」）を、`config.json` から消す。

```bash
python3 campus_chime.py --check
```

警告は「`config.json` の `extra_segment.mode` は v6.0.0 で廃止しました（…）。この行は無視します。消してください。」の形で、廃止した 8 キーのうち残っているものだけが出る（一覧は SPECIFICATION.md 3.4 章）。廃止した `mode="choice"` を使っていた場合は、天気を流したい時刻を `extra_segment.weather_hours` で指定する（例 `{ "extra_segment": { "weather_hours": [10, 12, 14, 16] } }`）。天気を流す時刻でも、ひとことは毎回流れる。

**無音になる文言があったら、その文言の作り置きが無い。** 読み上げ音声は文言との
完全一致で引いているため、文言（語尾・ひとこと・天気の地点や読み上げ項目）を変えたのに
PC 側で作り直していないと、変えた分だけ無音になる（放送本体は止まらない）。`git pull` だけでは
作り置きは増えない。声の無い文言は、`--check` の「作り置きの音声」に一覧で出る。作り直しの手順は
`docs/SETUP.md` 9 章 B を参照。

**それでも心当たりがない場合は `config.json` が古い可能性がある。** 旧版で作られた
`config.json` は当時の既定値を丸ごと抱えたままで、新しい既定値をすべて握りつぶす。
`--check` の「設定」に「既定値と同じ値です」という情報がいくつも並び、「作り置きの音声」で
時刻アナウンスの声がそろっていなければ該当する。**現地設定があれば退避してから**作り直す
（出力例・手順・理由は `docs/SETUP.md` 10-7 を参照）。

### 3-6. 点検と状態の読み方（`--check` / `--status` / `--wait-idle`）

`--check` と `--status` は、**鳴らさず、何も書きません**（ファイルもフォルダも作らず、権限も変えません）。放送の最中に実行しても影響しません。問い合わせるときは、この 2 つの出力を添えてください。

| コマンド | 見るもの | 終了コード |
|---|---|---|
| `python3 campus_chime.py --check` | 設置状態（設定・作り置きの音声・音源・書き込み先） | 0: 問題なし（警告だけでも 0）／1: NG あり |
| `python3 campus_chime.py --status` | いまの状態（版・時刻の同期・サービス・直近の放送・次の予定） | 0: 気になる点なし／1: 気になる点あり |
| `python3 campus_chime.py --wait-idle` | 放送の時間帯なら、終わるまで待つ（最大 360 秒） | 0: 放送の時間帯ではない（または終わった）／1: 待ちきれなかった |

`--version` と `--help` を除くどのオプションも、`config.json` を読めないとき（JSON の書き間違い・UTF-8 以外での保存）は、原因を日本語で表示して終了コード 2 になります。直してからやり直してください。

**`--check` の読み方。** 「設定」「作り置きの音声」「音源」「書き込み」の 4 つの節に、`OK`・`情報`・`警告`・`NG` の行が並びます。`NG` が 1 件でもあれば終了コード 1 で、`NG` の行には必ず「直し方」が付きます。`警告` と `情報` は放送を止めません（「直し方」が付くこともあります）。

「設定」の `NG` と `警告` の違いに注意してください。`NG` は、**サービスがその値では動けない**もの（存在しないタイムゾーン名、1 秒未満の待機時間、読めない数値、壊れたログの書式など）で、サービスは起動時にその項目**だけ**を既定値に置き換えて動きます（リストなら、壊れた要素だけを取り除きます）。`警告` は、サービスが動けはするものの、書いた意図とは違う動きになるもの（鳴らない時刻、曜日の書き間違い、`null` にした節など）で、**置き換えずに、書いたとおりに動きます**。直すのは自分です。

- **NG（置き換える）になるのは、次のような値だけです。** 存在しないタイムゾーン名／使えないログの水準の名前・書式／1 秒未満の待機時間（`schedule.max_sleep_seconds`）／起動・再生で例外になる数値（数値として読めない、範囲外、日時の範囲を出る）／時報の `start_hour`・`end_hour` が整数として読めない／閉館放送の時、時報・閉館放送の分が整数として読めない、または範囲外（その放送が有効なとき）／曜日や休みの時刻のリストが壊れている（壊れた要素だけ取り除く）／再生方式の指定が文字列でない、読み上げエンジンの指定がリストでない／VOICEVOX ENGINE の待ち時間（`tts.voicevox.timeout_seconds`・`probe_timeout_seconds`）が大きすぎる（約 92 億秒を超える。`tts.engines` に `voicevox` があるとき）／外部コマンドで再生する方式の表（`audio.commands`）の項目がコマンド（引数のリスト）でない（1 つの文字列で書いたものを含む。その項目だけを既定の項目に置き換える。再生方式 `audio.backend` が `mock` / `pygame` の間は表を読まないので、NG にならず警告にとどまる）／`schedule.hourly` などの節が数値や文字列に置き換わっている
- **警告（置き換えない）の例。** `"9"` や `9.0` のような書き方の違い／0〜23 の外の時刻／`start_hour` が `end_hour` より後ろ（時報は鳴らない）／曜日の `7` や `"1"`／`null` にした節（その放送は鳴らない。止めたいときは `enabled` を `false` にする）／知らない再生方式や読み上げエンジンの名前／`tts.engines` に `prerecorded` が無い（Pi では読み上げがすべて無音。置き換えない）／天気予報の待ち時間（`weather.timeout_seconds`）が大きすぎる（約 92 億秒を超える。天気予報が流れないだけで、放送は続く）／再生方式が `mock` / `pygame` の間の、壊れた `audio.commands`（表を読まないので動く。`command` にしたときに鳴らなくなる）／緯度・経度の範囲外／読み上げ文のテンプレートの置換名の誤り／`true` / `false` でない真偽値

一覧は SPECIFICATION.md 3.5 章にあります。

| 出ているもの | 意味 | 対処 |
|---|---|---|
| 設定 警告「…という設定キーはありません」（「もしかして …?」） | 綴りの違い。その行は無視されている | 綴りを直す |
| 設定 警告「…は v6.0.0 で廃止しました」 | 廃止した設定が残っている。値は無視される | その行を消す（3-3） |
| 設定 NG（存在しないタイムゾーン名・1 秒未満の待機時間・読めない数値など） | サービスは起動時にその項目だけ既定値に置き換えて動く（ログに ERROR で残る）。置き換えるのは NG だけ | 値を直す |
| 設定 警告「…は曜日に一致しません」「…の範囲外で、その時刻の時報は鳴りません」など | 値の誤りだが、サービスは動ける。**置き換えず、書いたとおりに動く**（意図と違う動きになる） | 「直し方」のとおりに直す |
| 設定 情報「…は既定値（…）と同じ値です」が多数 ＋ 作り置きの音声 NG（時刻アナウンスが 0/7 など） | 古い `config.json`（既定値の丸ごとコピー）が読み上げ文言を古いまま上書きしている | `docs/SETUP.md` 10-7 |
| 作り置きの音声 NG「N 件中 M 件の声がありません」 | その文は無音になる（先頭の 10 件まで一覧が出る） | PC で作り直して push し、Pi で更新する（`docs/SETUP.md` 9 章 B → A） |
| 作り置きの音声 NG「うち N 件はファイルがあるのに使えません」 | 空・壊れている・途中で切れている声のファイルがある（電源断などで起きる）。その文は無音になる | 「直し方」の `git checkout -- assets/voice` で戻す |
| 作り置きの音声 NG「フォルダ … が見つかりません」 | 読み上げがすべて無音になる | `git pull` が届いているか、設置場所を確認する（4-4） |
| 設定 警告「通信の待ち時間として設定できる範囲（±約 92 億秒）を出ています」（`weather.timeout_seconds`） | 天気予報の取得が毎回例外になり、天気予報が流れない。時報の読み上げとひとことは鳴り、放送は続く（置き換えず、書いたとおりに動く）。同じ文面が VOICEVOX ENGINE の待ち時間（`tts.voicevox.*`）に出るときは NG（疎通確認と合成が毎回例外になる） | `weather.timeout_seconds` を 8 など、ふつうの秒数に戻す |
| 設定 警告「今は audio.backend が mock か pygame なので使われませんが」（`audio.commands`） | 外部コマンドの表の書き方が間違っている（1 つの文字列で書いた、など）が、再生方式が `mock` / `pygame` の間は表を読まないので動く（置き換えず、書いたとおりに動く）。`command` にしたとき（pygame が無いときの `auto` を含む）に放送が鳴らなくなる。再生方式が `command` / `auto` のときは同じ誤りが NG になり、その項目だけが既定の項目に置き換わる | 「直し方」のとおり、コマンドを `["aplay", "-q", "{path}"]` のように引数のリストで書く |
| 設定 警告「… に prerecorded がありません」 | `tts.engines` から `prerecorded` を外している。Pi では作り置きを使わず、読み上げがすべて無音になる（置き換えず、書いたとおりに動く） | `tts.engines` を `["prerecorded", "voicevox"]` に戻す（PC で VOICEVOX ENGINE だけを使う開発用の設定を、Pi に持ち込んでいないか） |
| 作り置きの音声 NG「作り置きの声を使いません」 | 同じ原因。声がディスクにそろっていても、放送は作り置きを引かない。`--status` も「要確認」にする | 同上 |
| 作り置きの音声 NG「読み上げる文言を数えられません」 | 気温の幅・地点の `label`・読み上げ文のテンプレートの書式指定の幅などが大きすぎて、数え上げを省いた（理由と、直す設定のキーが続く）。起動時のログにも WARNING が出る | その設定を、実際に使う範囲に絞る（`weather.prerecord` の `temp_min`・`temp_max`、地点の `label`、書式指定の幅は 1000 以下） |
| ひとこと 警告 | `assets/quotes.json` が無い・読めない・空。内蔵の予備のひとこと 3 件だけで放送する | 「直し方」のとおり、`git checkout -- assets/quotes.json` で戻す |
| 音源 NG | 閉館アナウンス・蛍の光のファイルが無い・空・壊れている・途中で切れている（「音のデータが途中で切れています」など） | 「直し方」のとおり、`git checkout -- <ファイル>` で戻す |
| 音源 NG「途中で切れているか壊れています」 | 蛍の光（MP3）が、最後のフレームの途中で切れている・途中に MP3 でないデータが挟まっている・ID3 タグのあとにフレームが無い（電源断などで起きる。フレームをファイルの終わりまでたどって見つける。先頭の ID3 タグまでしか書けず、残りが 0 のファイルは、先頭の形も大きさも正しいが、タグのあとにフレームが無いので見つかる）。末尾の ID3v1 タグ・APEv2 タグ・1024 バイトまでの 0 埋めは正常 | 「直し方」のとおり、`git checkout -- assets/hotaru.mp3` で戻す |
| 音源 警告「… がまだありません（放送のときに自動で作ります）」 | 時報音がまだ無い | `bash scripts/setup.sh --no-apt` で作っておく |
| 書き込み NG「書き込めません」 | サービス（`pi`）が `cache/` に書けず、再生済みの記録が残らない。再起動のたびに同じ回が鳴る（4-6） | 「直し方」を実行する（下記） |
| 書き込み NG「… は sticky ビット付きのフォルダで、フォルダも既存のファイルも別の利用者の持ち物なので」 | `state.file` を `/tmp` のような共有フォルダに置き、その中の `state.json` が別の利用者（root など）のもの。置き換えて保存できず、再起動のたびに同じ回が鳴る | 「直し方」の `sudo chown`、または `state.file` を既定の `cache/` に戻す |
| 書き込み 警告 | 放送の履歴や音声のキャッシュを書けない。放送は止まらない | 「直し方」を実行する |
| 所有者 情報「root で実行しているため確認しません」 | root で実行したので、書き込めるかは調べていない | `pi` ユーザーで実行し直す |

書き込みの「直し方」は、設定が指す場所そのものにしか `chown` を案内しません。`cache/` がまだ無く、親にも書けないときは、そのフォルダだけを作って渡します。`/` や `/var/lib` のような親には触れません。

```
sudo mkdir -p /home/pi/campus-chime/cache && sudo chown pi:pi /home/pi/campus-chime/cache
```

`cache/` があるのに書けない（root の所有など）ときは、そのフォルダと中身を渡します。

```
sudo chown -R pi:pi /home/pi/campus-chime/cache
```

`/` や `/var/lib` のような OS の場所を設定が指しているときは、持ち主を変える案内を出さず、設定を書ける場所に変えるよう案内します。`cache/` の中に root 所有の**ファイル**が残っているだけなら、`cache/` に書ける限り、アプリは一時ファイルから置き換えて保存できるので、NG にはなりません。ただし、`state.file` を `/tmp` のような sticky ビットのフォルダに置いている場合は別で、フォルダも既存の `state.json` も別の利用者の持ち物だと、置き換えを OS に断られるので NG になります（既定の `cache/` には当てはまりません）。

**`--status` の読み方。** 1 行目が版とコミットです（手元のコードのもので、サービスが今その版で動いているとは限りません。更新が途中で止まったときの見分け方は 3-3）。そのあとに「現在時刻」「時刻の同期」「サービス」「自動起動」「再生方法」「作り置きの音声」、「直近の放送」（新しい順に 8 件まで）、「次の予定」（3 件）が続きます。気になる点があると、末尾に「要確認:」として理由が並びます（終了コード 1。「時刻の同期」「サービス」「再生方法」「作り置きの音声」の行は、行末にも「← 要確認」が付きます）。無ければ末尾は「気になる点は見つかりませんでした。」です。

| 要確認の理由 | 対処 |
|---|---|
| 時刻が NTP と同期していません | 4-5 |
| サービス campus_chime.service が動いていません | `sudo systemctl status campus_chime.service` と `journalctl -u campus_chime.service -n 50`（4-8） |
| 再生方法が mock です（実機のみ） | 音が出ません。`docs/SETUP.md` 10-2 |
| 直近の放送が失敗しています | 下の「直近の放送」を読む |
| 直近の放送で、音源ファイルが無くて鳴らせなかった部分があります | 同梱の音源が欠けている。`--check` の「音源」を見て、「直し方」で戻す |
| 直近の放送は、内容を組み立てられず簡易の内容で鳴りました | 時報音だけ（閉館放送なら閉館アナウンスと蛍の光だけ）で鳴った。時刻アナウンスとひとことが入っていない。結果は「成功」のままなので、「直近の放送」の行末の「簡易の内容で放送」で見分ける。`journalctl -u campus_chime.service` で、そのときの ERROR（「再生内容の組み立てに失敗しました」）の原因を見る |
| tts.engines に "prerecorded" が無いため、作り置きの声を使いません。Pi では読み上げがすべて無音になります | 放送が作り置きを引かないので、声がそろっていても無音になる。`tts.engines` を `["prerecorded", "voicevox"]` に戻す（上の表の、設定の警告の行） |
| 作り置きの音声が N 件足りません／数えられません | `--check` で一覧と理由を見る |

「確認できません」と出た項目（`timedatectl` や `systemctl` が無い開発機など）は、問題とは数えません。「自動起動」が「無効」でも「要確認」にはならないので、「有効」になっているかは自分の目で確かめます（電源を入れ直したときに自動で始まるかどうか）。

**「直近の放送」の読み方。** 常駐が実際に放送した結果で、1 行が 1 回の放送です（`--test-hourly` などの試し鳴らしと `--dry-run` は残りません）。

```
10/09 16:57  閉館放送  成功
10/09 10:00  時報      成功  簡易の内容で放送
10/08 16:57  閉館放送  一部のみ  欠けた音源: 「閉館アナウンス」
10/08 12:00  時報      一部のみ  無音: 「今の大津の天気はくもりなのだ。」
10/07 16:57  閉館放送  エラー  エラー: 音源ファイルが見つかりません: /home/pi/campus-chime/assets/hotaru.mp3
10/07 10:00  時報      失敗
```

| 結果 | 意味 |
|---|---|
| 成功 | 予定の部品がすべて鳴った（音源ファイルが無くて積めなかった部品も無い） |
| 一部のみ | 鳴ったが、一部が鳴らなかった。「無音:」にその文言が出る（3 件まで。ほかは件数）。「欠けた音源:」には、音源ファイルが無くて組み立てのときに積めなかった必須の部品（時報音・閉館アナウンス・蛍の光）が出る。直近の 1 回に欠けた音源があると、`--status` が「要確認」にする（鳴った部品の数だけを見ると成功に見えて、閉館アナウンスだけが鳴らなかった、ということがあるため） |
| 失敗 | 1 つも鳴らせなかった |
| エラー | 放送が例外で終わった。「エラー:」に説明が出る |

行末の「簡易の内容で放送」は、放送の内容を組み立てられず、最小の内容（時報音だけ、閉館放送なら閉館アナウンスと蛍の光だけ）で鳴らしたことを表します。鳴らせた部品はすべて鳴ったので結果は「成功」のままですが、時刻アナウンスやひとことは入っていません。直近の 1 回がこれだと、`--status` が「要確認」にします（原因はそのときの ERROR ログ）。

履歴は `cache/history.jsonl` に 1 回の放送につき 1 行（JSON）で残り、600 行を超えると新しい 500 行だけに書き直されます。書けなくても放送は止まらず、ログに警告が出るだけです。履歴だけを消したいときは、このファイルを消して構いません（放送の動作には影響しません）。

**`--wait-idle` の使いどころ。** サービスを手で再起動する前に、放送の時間帯でないことを確かめます。放送の時間帯とは、準備を始める 10 秒前から、時報は再生開始の 90 秒後、閉館放送は 300 秒後までです。

```bash
python3 campus_chime.py --wait-idle && sudo systemctl restart campus_chime.service
```

## 4. トラブル対処

### 4-1. 時間になっても鳴らない

順に確認します。

```bash
# ① サービスは動いているか。直近の放送はどうだったか（読み方は 3-6）
python3 campus_chime.py --status

# ② その時刻は予定に入っているか（曜日・時間帯・skip_hours）
python3 campus_chime.py --schedule 20

# ③ その時刻のログに何が出ているか
journalctl -u campus_chime.service --since "today 09:55" --until "today 10:05" --no-pager

# ④ そもそも音が出る状態か
speaker-test -t sine -f 440 -c 2 -l 1
```

| ログに出ていること | 意味 | 対処 |
|---|---|---|
| `再生開始` は出ているが聞こえない | アプリは鳴らしている | 音量・配線・出力先（4-2） |
| `再生開始` が無い | 予定に入っていない／サービスが落ちていた | `--schedule` と `--status` |
| `再生開始時刻を … 過ぎています` | 起動が遅れて追いかけ再生した | 正常（起動直後に多い） |
| `音声合成に失敗` | 読み上げだけ不可 | 4-4 |
| 起動時に `設定の誤り: …`（ERROR） | 危ない値を既定値に置き換えて動いている | `--check` の「設定」で直し方を見る |
| 起動時に `作り置きの音声が N 件ありません`（WARNING） | その文は無音になる | `--check` と 4-4 |
| 起動時に `作り置きの音声の数え上げを省きました`（WARNING） | 気温の幅など、作り置きする文言が多すぎる設定。起動を遅くしないために数えていない（放送は止まらない） | `weather.prerecord.temp_min` / `temp_max` を、実際に出る値（例: -5〜40）に絞る。`--check` の「設定」に警告が、「作り置きの音声」に NG（数えられません）が出る |
| `天気予報を取得できませんでした` | 天気予報が無効（古い `config.json` が多い）、またはネットワーク断・時刻のずれ | 続く文言で見分ける。「無効化されています」なら SETUP.md 10-7、「全地点で失敗」なら SETUP.md 10-5。時報とひとことは鳴る |

`--status` の「直近の放送」（新しい順）に、その時刻の放送がどう終わったかが残っています。

| 「直近の放送」に出ていること | 意味 | 対処 |
|---|---|---|
| その時刻の行が無い | 放送されなかった（サービスが落ちていた、予定に入っていない） | `--schedule` と、その時刻のログ（③） |
| 失敗／エラー | 放送を試みたが、1 つも鳴らせなかった。エラーの説明が付く | 音の問題は 4-2、音源の欠落は `--check` |
| 一部のみ（「無音: 「…」」） | 鳴ったが、その文言だけ無音だった | 4-4 |
| 一部のみ（「欠けた音源: 「…」」） | 鳴ったが、音源ファイルが無くて、その部品（時報音・閉館アナウンス・蛍の光）だけ鳴らなかった | `--check` の「音源」を見て、「直し方」で戻す |

### 4-2. 音が出ない

[SETUP.md 10 章](SETUP.md#10-音が鳴らないとき) に切り分け手順があります。要点だけ:

```bash
speaker-test -t sine -f 440 -c 2 -l 1   # OS で鳴るか
aplay -l                                # デバイスが見えるか
alsamixer                               # ミュートでないか
groups pi                               # audio グループに入っているか
```

### 4-3. 音が途切れる・カクつく

1. 電源を 5V 2.5A 以上のものに替える（最も多い原因）
2. `config.json` で `audio.mixer.buffer` を `8192` に上げる
3. 他の常駐プロセスを入れていないか確認する（本機は専用機）

```json
{ "audio": { "mixer": { "buffer": 8192 } } }
```

### 4-4. 読み上げだけ鳴らない（時報音は鳴る）

読み上げ音声の作り置きが見つからないか、`config.json` が古い（[SETUP.md 10-7](SETUP.md#10-7-読み上げが無音になる)）かのどちらかです。時報音は合成不要なので鳴ります。

```bash
python3 campus_chime.py --test-hourly --log-level DEBUG   # ログの TTS: を確認
python3 campus_chime.py --check                            # 「作り置きの音声」に、声の無い文言が出る
```

`--check` の「作り置きの音声」が「138 件すべてそろっています」なら、作り置きは揃っています。`prerecorded(利用不可)` なら `assets/voice/` が見つかっていません（`--check` に「フォルダ … が見つかりません」と出ます。`git pull` が届いているか確認）。Pi 上では VOICEVOX ENGINE を動かさない運用のため `voicevox(利用不可)` は正常です。一部の文言だけ無音の場合は「3-3. 更新を取り込む」または [SETUP.md 10-7](SETUP.md#10-7-読み上げが無音になる) を参照してください。

### 4-5. 時刻がずれている

本機は RTC 非搭載です。

```bash
python3 campus_chime.py --status   # 「現在時刻」が JST か、「時刻の同期」が「同期済み（NTP）」か
timedatectl
# Time zone: Asia/Tokyo / System clock synchronized: yes を確認

sudo timedatectl set-timezone Asia/Tokyo
sudo systemctl restart systemd-timesyncd
```

同期しない場合は Wi-Fi 接続と DNS を確認してください。

### 4-6. 同じ回が 2 回鳴った

再生済みの記録（`cache/state.json`）を保存できていない可能性があります。root で実行した跡で `cache/` が root 所有になり、サービス（`pi`）が書き込めないと、再生済みの記録が残らず、再起動のたびに同じ回が鳴ります。

```bash
python3 campus_chime.py --check   # 「書き込み」に NG が出ていれば原因。「直し方」を実行する
cat /home/pi/campus-chime/cache/state.json
```

「直し方」は、`cache/` が無いなら `sudo mkdir -p /home/pi/campus-chime/cache && sudo chown pi:pi /home/pi/campus-chime/cache`、あるのに書けないなら `sudo chown -R pi:pi /home/pi/campus-chime/cache` の形で出ます（3-6）。`/` や `/var/lib` のような OS の場所を設定が指していれば、`chown` は案内されず、設定を書ける場所に変えるよう案内されます。`cache/` の中に root 所有のファイルが残っているだけなら、`cache/` に書ける限り、保存はできるので `--check` は NG にしません。

`--check` が無い古い版のときは、`sudo chown -R pi:pi /home/pi/campus-chime` で所有者を戻します。

### 4-7. 天気予報が古い／いつも同じ

天気予報は既定で有効です（取得先は Open-Meteo）。取得結果は 60 分キャッシュされます。すぐに反映したい場合はサービスを再起動してください。

```json
{ "weather": { "cache_minutes": 30 } }
```

### 4-8. サービスが再起動を繰り返す

```bash
journalctl -u campus_chime.service -n 100 --no-pager
```

`Restart=always` のため 10 秒ごとに再起動します。設定ファイルの JSON 書式エラーが典型的な原因です。

```bash
cd /home/pi/campus-chime
python3 campus_chime.py --check          # 壊れていれば、原因を日本語で表示して終了コード 2 になる
# エラーが出たら書式を直す。応急処置として config.json を退避すれば既定値で動く
mv config.json config.json.bak
sudo systemctl restart campus_chime.service
```

### 4-9. Wi-Fi が切れる

Pi 3B は **2.4GHz 帯のみ**対応です。5GHz の SSID には接続できません。

```bash
iwconfig wlan0
sudo iw dev wlan0 set power_save off   # 省電力による切断を防ぐ（応急）
```

天気予報以外は Wi-Fi なしでも動作するため、放送そのものは止まりません。

## 6. 設計上の重要な決定（背景）

保守時に「なぜこうなっているのか」で迷わないための記録。

| 決定 | 理由 |
|---|---|
| 長音の**開始**を正時に合わせる | NHK の時報と同じ作法。短音 3 回は「正時の 3 秒前から」始まる。そのため `--schedule` の「再生開始」は正時より 3 秒早い |
| 天気取得・読み上げ音声の用意を再生の 45 秒前に済ませる | ネットワークや音声の読み込みに時間がかかっても、再生開始時刻がずれないようにするため |
| `sleep` を 30 秒ごとに分割する | RTC 非搭載機は起動直後に NTP で時刻が大きく飛ぶ。長い `sleep` では追従できない |
| 再生済みをディスクに保存する | `Restart=always` のため、クラッシュ後の再起動で同じ回が二度鳴るのを防ぐ |
| 天気の取得に失敗しても放送は止めない（天気だけ黙って飛ばす） | 時報が鳴らない方が問題が大きいため。ひとことは天気の成否に関係なく毎回流す（v3 までは失敗時にひとことへ切り替えていた） |
| 読み上げ音声をすべて作り置きして同梱する（Pi 上の音声合成ゼロ） | Pi 3B では VOICEVOX を動かせない。実行時に合成すると別人の声になったり（v4 まで）、合成できず無音になったりするため、全文言を PC で作り置きし文言との完全一致で引く。文言を変えたら PC で作り直す |
| 時報音をコードで合成する | 音源ファイルの権利関係・調達を不要にし、周波数や長さを設定で変えられるようにするため |
| pygame 以外に外部コマンド再生を用意する | Lite 環境で pygame が壊れても放送を継続できるようにするため |
| `config.json` を Git 管理外にする | 現地で編集したファイルが `git pull` と衝突しないようにするため |
| ランタイムが動けない設定値（error）だけ、起動時にその項目だけ既定値へ置き換えて動かす（ログに ERROR で残す）。動ける値の誤りは warning にとどめ、置き換えない | 異常終了させても、`Restart=always` で再起動を繰り返すだけで時報が鳴らないため。一方、動ける値まで置き換えると、設定を変えていないのに放送が変わってしまう（例: 曜日のリストに `7` が混ざっていても土曜は鳴り続けていた）。書き間違いは `--check` で先に見つける |
| `--check` / `--status` は鳴らさず、何も書かない | 現地で気軽に、放送の最中でも実行できるようにするため。問い合わせの出力にもそのまま添えられる |
| 放送の履歴（`cache/history.jsonl`）を書けなくても放送は止めない | 履歴は `--status` で振り返るための付け足し。履歴のために時報を落としては本末転倒のため |
| 音源ファイルが無くて積めなかった部品は、履歴の `missing` に別に残す（結果は「一部のみ」） | 積めなかった部品は再生の件数に現れないので、件数だけを見ると「すべて鳴った」ことになり、閉館アナウンスが無いまま「成功」と表示されてしまうため |
| `update.sh` は、止まるときは何も変えず、元の版へ戻す手順は表示するだけにする | 運用中の機械を、更新の途中で半端な状態にしないため。戻す操作は人が確かめてから実行する |
| `setup.sh` が再起動に成功したときのコミットを `cache/deployed_commit` に記録し、`update.sh` はそれがいまの版と合わなければ、すでに最新版でも続きを反映する | 取り込みのあとで止まった（放送の時間帯が終わらない・`setup.sh` の失敗）あとにもう一度実行したとき、「すでに最新版です」で終わると、サービスが古い版のまま気づかれないため |
