# キャンパス時報システム 要件定義書

**プロジェクト名:** Campus Chime System
**バージョン:** 6.2.0（新機能: 休館日・放送の一時休止・種類ごとの音量・停止要求ですぐ止まる再生、安全面の点検と強化）
**対象ハードウェア:** Raspberry Pi 3 Model B（Headless）
**初版作成日:** 2025/11/30
**改訂日:** 2026/10/24

---

## 1. 目的

大学施設において、

1. **平日 10:00〜16:00 の毎正時**に時報を放送し、校内の時間感覚をそろえる
2. **平日 16:57** に合成音声によるアナウンスと「蛍の光」を放送し、閉館時刻の接近を知らせる

職員による手動放送を不要にし、**無人・無操作で毎日確実に定刻放送が行われる状態**を維持することを最終目的とする。

### 2.2 v1.x 運用で判明した課題

| # | 課題 | 影響 |
|---|---|---|
| 1 | 音声再生時に音飛び・カクつきが発生 | 放送品質の低下。pygame mixer のバッファ既定値（512 サンプル）が Pi 3B に対して小さく、バッファアンダーランを起こしていたと推定 |
| 2 | デスクトップ環境の常駐によるリソース圧迫 | RAM 1GB の本機において GUI が常時メモリ・CPU を占有 |
| 3 | `weather.py` との競合を `pkill` で回避する設計 | 根本解決ではなく対症療法。競合プロセスの生存状況に依存し不安定 |
| 4 | ドキュメントと systemd ユニットのパス不一致 | README は `~/steam5pm`、ユニットは `/home/pi/campus-chime` を指しており、手順どおりに導入すると **サービスが起動失敗する** |
| 5 | ドキュメント間・コードコメント間の時刻表記揺れ | 実装は `16:57` だが、KNOWLEDGE_BASE およびコードコメントは `17:00` 表記。保守時の誤解を招く |
| 6 | 放送内容・時刻がコードに直書き | 変更のたびにコード改変が必要で、運用担当者が手を出しにくい |
| 7 | 二重再生防止がプロセスのメモリ上のみ | サービス再起動で「本日再生済み」の記録が失われ、同じ回が再度鳴りうる |

### 2.3 v3.0.0 の方針

- OS を Raspberry Pi OS **Lite** に入れ替え、デスクトップ環境を撤去する（課題 2）
- `weather.py` は環境ごと廃止し、**競合排除ロジック自体を削除**する（課題 3 の根本解決）
- 音声安定性を非機能要件として明文化し、mixer 初期化パラメータを仕様として固定する（課題 1）
- パス・時刻の表記をリポジトリ全体で統一する（課題 4・5）
- **放送内容・時刻・地域を設定ファイル（`config.json`）へ外出しする**（課題 6）
- **再生済み状態をディスクへ永続化する**（課題 7）
- **時報機能を新規に追加する**（本版の主目的）

> **v2.0.0 からの方針変更（天気予報）**
> v2.0.0 では「天気予報放送機能は提供しない（廃止）」としていたが、v3.0.0 では
> **時報のあとのおまけ**として天気予報を再導入する。ただし v1.x の `weather.py`
> （常駐する別プロセス）を復活させるのではなく、**本アプリが必要時にだけ
> 外部 API を呼ぶ**方式とし、取得失敗時は「ひとこと」に自動で切り替える
> （v4.0.0 以降は、天気だけを飛ばしてひとことは必ず流す。FR-03 参照）。
> これにより、課題 3（プロセス競合）は再発しない。

### 2.4 v4.0.0 の方針

- **読み上げをずんだもんの声と「なのだ」調に統一する。** 声だけ替えて文言が事務的な
  ままではキャラクターと合わないため、語尾も揃える
- **読み上げる文言をすべて事前生成して同梱する。** 実機での音声合成をゼロにし、
  声が混ざらないようにする
- **天気予報を「今日 1 日の予報」から「現在の天気と気温」に変える。** 時報で知りたいのは
  今どうなのかであり、その日の予想最高気温を午後に読んでも実感と合わない
- **天気予報を 2 時間おきに流す。** 毎正時だと放送が長くなりすぎる

> **天気予報の取得先を気象庁から Open-Meteo へ変更し、気象庁の取得先を削除した理由**
> 天気の文面は日替わりのため、そのままでは事前生成できない。事前生成が外れた文言は
> **その文だけ無音**になる。気象庁の予報文は自由文で語彙が閉じないが、Open-Meteo は
> 天気コード（28 語）で閉じる。読み上げを地名・気温それぞれの文に分割すれば全パターンを
> 作り置きでき、放送全体を 1 つの声で揃えられる。精度より**声の一貫性**を優先した判断である。
> v4.0.0 では既定の取得先を Open-Meteo に変えたが、設定で気象庁にも戻せた。戻すと天気だけ
> 無音になるうえ、気温の文も出なくなるため、v5.3.0 で廃止を予告し、**v6.0.0 で気象庁の
> 取得先を削除**した（取得先は Open-Meteo だけ）。

### 2.5 v5.0.0 の方針

- **作り置き・VOICEVOX ENGINE のどちらにも無い文言を実行時合成する最終フォールバック
  （Open JTalk）を、コードごと削除する。** 読み上げエンジンは「作り置き → VOICEVOX
  ENGINE」の 2 段のみとし、どちらでも合成できない文言は**その 1 文だけ無音**にする
  （時報音・蛍の光・他の文言は鳴り、放送本体は止めない）
- Raspberry Pi 上では VOICEVOX ENGINE を動かせない（armhf 向けビルドが無い）ため、
  **実機では実質「作り置きのみ」**になる。現在は 138 文言すべてが作り置き済みで、
  実機での実行時合成は 0 件

> **なぜフォールバックそのものを削除するのか**
> 「作り置きに無い文言は別人の男性音声になる」という設計（2.4 参照）は、2.2 の課題
> 一覧にはなかった新しい問題を生んだ。**フォールバックが存在する限り、壊れていても
> 音は鳴ってしまう。** 実際に、この症状は 3 回表面化した——(1) 天気の文面が日替わりで
> 作り置きできず天気だけ男性音声になりかけた（→ 語彙を有限に絞って解決）、
> (2) 語尾を「なのだ」調に変えたあと作り置きを作り直さないまま配りかけた、
> (3) 古い `config.json` が文言を上書きし、実機で読み上げが全部男性音声になった。
> いずれも「それらしく鳴っている」ために、放送に立ち会うまで異変に気づけなかった。
> **壊れた状態で「それらしく」鳴ってしまうことは、無音より害が大きい**と判断し、
> フォールバックそのものを廃した。無音は聞き逃しやすい分、`--test-hourly` の警告表示や
> journalctl の ERROR ログで機械的に検出できるようにする（詳細は `docs/SETUP.md` の
> 「10-7. 読み上げが無音になる」）。

### 2.6 v6.1.0 の方針（運用の道具）

- **現地で、鳴らさず・書かずに、状態を確かめられるようにする。** 無音は聞き逃しやすく、
  設定の書き間違いや root で実行した跡は、放送に立ち会うまで気づけない（2.5 参照）。
  設置状態の点検（`--check`）と、いまの状態の表示（`--status`）を用意し、導入・更新・
  問い合わせの手順にある手作業の確認（ファイルを数える、`grep` する、`journalctl` を
  絞り込む）を置き換える
- **放送の結果を残す。** 放送されなかった、または一部が無音だった事実を、あとから現地で
  確かめられるようにする（`cache/history.jsonl`）。書けなくても放送は止めない
- **更新を 1 つのコマンドにする。** 取り込み・放送中の待機・点検・再起動・結果の表示を
  `scripts/update.sh` にまとめ、手順の抜け（放送中の再起動、点検の飛ばし）を防ぐ。
  止まるときは何も変えない
- **設定の書き間違いで放送を止めない。** ランタイムが動けない値（起動時や予定・再生で
  例外になる、待機ループが CPU を使い続ける、タイムゾーンが解決できない、など）は、
  起動時にその項目だけ既定値に置き換えて動かす（異常終了させても、systemd が再起動を
  繰り返すだけで時報は鳴らない）。**ランタイムが動ける値は警告にとどめ、置き換えない**
  （前の版が動かしていた放送を、検査が変えてしまわないため）
- 読み上げる文言と作り置きの音声は変えない（この版で増える文言は無い）

### 2.7 v6.2.0 の方針（休む日・音量・安全な停止）

- **休む日を、設定とコマンドで扱えるようにする。** 学園祭や年末年始のように前もって分かっている
  休みは、設定に日付を書く（`schedule.closures`。FR-14）。行事や点検でその日に決まった休みは、
  サービスを止めずに、コマンド 1 つで放送だけを止める（`--pause-today` / `--pause-until`。FR-15）。
  どちらも**既定では何も変わらない**（休館日は空、止めてもいない）
- **祝日は自動では休まない。** 祝日も開館する（鳴らす）のが運用者（オーナー）の判断であり、祝日を暦や外部 API で判定すると、
  開館する日に鳴らなくなる危険のほうが大きい。休む祝日は、人が休館日に書く
- **休む日の機能は、失敗したら鳴らす側に倒す。** 休館日の書き間違いも、休止の記録の破損も、
  放送を止める原因にしない（その項目だけ無視する／止めていないものとして鳴らす）。時報の
  「ポーン」を遅らせる処理も入れない。止めたまま忘れないよう、止められるのは最長 31 日までにする
- **音量を種類ごとに設定ファイルで絞れるようにする**（FR-16）。OS（ALSA）の音量は高めに固定し、
  アプリ側で絞る運用にする（ALSA は全体で 1 つの音量しか持たず、設定ファイルにも残らない）
- **停止要求に、再生中でも応じる**（FR-17）。以前は再生が終わるまで止まらず、蛍の光の途中で停止・
  再起動すると systemd が約 90 秒待って強制終了していた。1 つの音源が鳴り終わらない場合も、
  上限の秒数で打ち切る
- **運用中の機械の安全面を、点検でき、手順ごとに強化できるようにする**（NFR-08）。Pi は学内のネットワークからだけ届く前提だが、大学は広い範囲のグローバルなアドレスを持つことがあり、Pi が学外から届くかもしれない。そこで、現状を読むだけで点検する道具（`scripts/security_check.sh`）と、見つかった点を直す道具（`scripts/harden.sh`）を分けて用意する。強化は**手順ごとに選べて、どれも元に戻せ**、締め出される恐れのある変更（SSH・防火壁）は、確定しなければ自動で元に戻る。放送の時刻と内容は変えない
- 読み上げる文言と作り置きの音声は変えない（この版で増える文言は無い）

## 3. スコープ

### 3.1 対象範囲

- 毎正時の時報放送機能（新規）
- 時報後の「ひとこと／天気予報」放送機能（新規）
- 定刻の閉館放送機能
- systemd による常駐・自動復旧
- 設定ファイルによる運用時変更
- 開発環境（WSL 等）での Mock 動作
- 現地での設置状態の点検・状態の確認・更新のための道具（`--check` / `--status` / `scripts/update.sh`）
- 休館日の設定と、放送の一時休止（`schedule.closures` / `--pause-today` / `--pause-until` / `--pause-off`）
- 種類ごとの音量の設定（`audio.volume`）と、停止要求・打ち切りに対する再生の安全な止め方
- 運用中の Pi の安全面の点検と、手順ごとの強化（`scripts/security_check.sh` / `scripts/harden.sh`）、運用者向けの手引きと脆弱性の報告の窓口（`docs/SECURITY.md`）
- 上記に付随するドキュメント整備・自動テスト

### 3.2 対象外（Non-Goals）

- 祝日・休講日・入試期間等の**自動判定**（暦や外部 API による判定。休む日は、人が設定の休館日に書く。FR-14。祝日は自動では休まない）
- 音量の遠隔調整、放送内容の遠隔差し替え（音量は現地の設定ファイルで変える。FR-16）
- Web UI・管理画面の提供
- ブラウザ等の GUI 用途（Lite 化により本機では不可となる）
- 常駐型の天気予報ボット（`weather.py`）の復活

## 4. システム構成

### 4.1 ハードウェア構成

| 項目 | 内容 |
|---|---|
| ホスト | Raspberry Pi 3 Model B |
| CPU / RAM | クアッドコア 1.2GHz / 1GB |
| ネットワーク | 内蔵 Wi-Fi（**2.4GHz 帯のみ対応**。5GHz 非対応） |
| オーディオ出力 | 3.5mm ジャック接続スピーカー または USB スピーカー |
| RTC | **非搭載**（電源断で時刻が保持されない。→ NFR-04） |

### 4.2 ソフトウェア構成

| 項目 | 内容 |
|---|---|
| OS | Raspberry Pi OS **Lite 32bit**（Bookworm 系）／Headless 運用 |
| 言語 | Python 3.9 以上（Bookworm 標準は 3.11） |
| 音声再生 | pygame（SDL2 mixer）。副系として `aplay` / `mpg123` |
| 音声合成 | 事前生成済み音声（VOICEVOX:ずんだもん、`assets/voice/`）を再生。任意で VOICEVOX ENGINE（HTTP API）による実行時合成をフォールバックに持てるが、Pi 上では動かさない（実行時合成のフォールバックは v5.0.0 で撤廃） |
| 天気予報 | Open-Meteo（API キー不要）。天気コードで語彙が閉じ、読み上げを事前生成できるため、取得先はこれだけとする（2.4 参照） |
| プロセス管理 | systemd |
| デプロイ | Git / GitHub（Pi での更新は `scripts/update.sh`） |
| 実行ユーザー | `pi` |
| 設置パス | `/home/pi/campus-chime` |

> **32bit を選定する理由:** 本機は RAM 1GB であり、64bit 版はメモリ消費が相対的に大きい。GUI を持たない専用機用途では 32bit 版の方が余裕を確保しやすいため。

> **外部ライブラリを増やさない方針:** 天気取得・時報音生成は標準ライブラリで完結させ、読み上げは事前生成済みの音声ファイルを再生するだけにする（Pi 上で音声合成は行わない）。pip 依存は pygame のみとし、OS 更新時の破損リスクを抑える。

## 5. 機能要件（Functional Requirements）

### FR-01 時報スケジューリング（新規）

- トリガー時刻: **平日の 10:00〜16:00 の毎正時（JST）**（既定値。設定で変更可）
- 長音「ポーン」の**先頭が正時ちょうど**に鳴ること
- 対象時間帯・分・曜日・除外時刻を設定ファイルで変更できること

### FR-02 時報の内容（新規）

以下の順序で、途切れなく再生すること。

1. **時報音**
   - 440Hz の短音（100ms）を 1 秒間隔で 3 回
   - 続いて 880Hz の長音（1000ms）を 1 回。**この長音の開始が正時**
   - 音源はアプリが実行時に合成する（音源ファイルの外部調達を不要とする）
2. **時刻アナウンス**
   - 「{午前|午後}{N}時をお知らせしたのだ。」
   - 12:00 は「正午をお知らせしたのだ。」
   - 文言はテンプレートとして設定ファイルで変更できること

### FR-03 おまけ放送（新規）

- 時刻アナウンスのあとに、**天気予報（流す時刻のみ）→「ひとこと」**の順に再生する。
  抽選や「どちらか一方を選ぶ」分岐は無い（1 経路）
- **天気予報は 12 時の 1 回**（既定）に流す。対象外の時刻は
  「ひとこと」のみとし、**天気 API を呼ばない**こと。流す時刻は設定（`extra_segment.weather_hours`）で変えられる
- 天気予報は**現在の天気と現在の気温**を読むこと。今日 1 日の予報（最高気温・降水確率）は
  設定で有効にできるが、既定では読まない
- 天気予報は**複数地点**に対応すること（既定は大津の 1 地点。複数設定した場合は上から順に読む）
- **天気予報の取得に失敗した場合は、その回の天気を飛ばす**こと。「ひとこと」は
  必ず後続で流れるため放送は沈黙せず、ここで「ひとこと」へ切り替えると 2 つ流れてしまう
- 従来の「どちらか一方を選ぶ」方式は v6.0.0 で廃止した（`extra_segment.mode="choice"` と関連設定）。
  天気を流す時刻の指定（`weather_hours`）に一本化した
- 「ひとこと」は直近に使ったものを避けて選ぶこと
- 「ひとこと」は編集可能なデータファイル（`assets/quotes.json`）で管理すること
- **閉館放送には天気予報を付けない**こと

### FR-04 閉館放送

- トリガー時刻: **平日 16:57:00（JST）**（既定値。設定で変更可）
- 以下の順序で、途切れなく再生すること。
  1. **アナウンス再生（Pre-Roll）**: `assets/announce.wav`（VOICEVOX:ずんだもん）。フェードなし、即時再生。**完全に終了するまで次の処理を待機**
  2. **楽曲再生（Main Content）**: `assets/hotaru.mp3`（Auld Lang Syne）。再生開始時に **2000ms** かけてフェードイン

### FR-05 平日限定稼働

- 月曜日から金曜日のみ稼働する（既定）
- 稼働曜日は時報・閉館放送それぞれ独立に設定できること
- **祝日は自動では休まない**（平日であれば祝日でも再生される。祝日も開館する（鳴らす）という運用者（オーナー）の判断で、制約ではない）。休む日は FR-14 の休館日に書く

### FR-06 二重再生防止

- 同一日付・同一イベントは 1 回のみ再生する
- 最終再生日を**ディスクへ永続化**し、サービス再起動をまたいでも二重再生しないこと
- 日付が変わることで自然にリセットされる方式とする

### FR-07 取りこぼし防止（追いかけ再生）

- 再起動等により再生開始時刻を過ぎて起動した場合、**一定時間内（既定 120 秒）であれば当該回を再生**すること
- それを超えた場合は当該回を見送り、次回の予定へ進むこと

### FR-08 環境自動判定（Cross-Platform）

- 実行環境（Linux 実機 / WSL 開発環境）を自動判定する
- WSL 上では音声出力を行わず、ログ出力と `time.sleep` による時間経過シミュレーションのみを行う（Mock Mode）
- 実機で pygame が使えない場合は外部コマンド（`aplay` / `mpg123`）へフォールバックすること

### FR-09 テスト・確認モード

起動引数により、時刻を待たずに次の確認ができること。

| 引数 | 内容 |
|---|---|
| `--test-hourly [HOUR]` | 時報を即時再生 |
| `--test` | 閉館放送を即時再生 |
| `--test-all` | 時報 → 閉館放送を続けて再生 |
| `--weather` | 天気予報の読み上げ文を確認 |
| `--say TEXT` | 任意文言の読み上げ |
| `--schedule [N]` | 次回以降の予定を表示 |
| `--dry-run` | 音を出さず、再生内容のみ表示 |
| `--generate-assets` | 時報音を生成し、時刻アナウンスの音声を用意できるか確認 |
| `--check` | 設置状態の点検（FR-11） |
| `--status` | いまの状態の表示（FR-12） |
| `--wait-idle [SECONDS]` | 放送の時間帯なら、終わるまで待つ（FR-13） |
| `--pause-today` | 今日の時報と閉館放送を止める（FR-15） |
| `--pause-until YYYY-MM-DD` | その日（含む）まで止める。今日から最長 31 日（FR-15） |
| `--pause-off` | 止めている放送を再開する（FR-15） |
| `--reason TEXT` | 止める理由（`--pause-today` / `--pause-until` と一緒に。FR-15） |
| `--version` | 版とコミットの表示（FR-12） |

### FR-10 設定の外部化

- 時刻・曜日・読み上げ文言・天気の地域・音声合成の設定を、**コードを書き換えずに** `config.json` で変更できること
- `config.json` は Git 管理外とし、`git pull` による更新で衝突しないこと
- 全項目の雛形として `config.example.json` を同梱すること
- 読み上げ文言や天気の地点を変えたときは、Pi の `config.json` を PC に持ってきて `scripts/generate_voicevox.py --config` に渡し、読み上げ音声を作り直せること（生成する文言は、その設定の文言に既定の設定の文言を足したもの）

### FR-11 設置状態の点検（`--check`）

- 現地で、鳴らさずに、次を点検できること（`python3 campus_chime.py --check`）
  - **設定:** 書き間違い（知らないキー・廃止したキー・範囲外や型違いの値・綴りの違い）。サービスが動けない値は NG、動けるが意図と違う値は警告として区別する
  - **作り置きの音声:** 放送で読み上げる全文言に声があるか（声の無い文言は一覧で示す。空・壊れた・途中で切れた声のファイルは「無い」ものとして数える）。`tts.engines` に `prerecorded` が無いと、声がそろっていても Pi では読み上げがすべて無音になるので NG にする。設定の値で文言が多すぎる・長すぎて数えられないときは、理由と直す設定を示す
  - **音源:** 閉館アナウンス・蛍の光・時報音のファイルが、空でなく、最後まで読めるか（電源断などで途中までしか書けなかったファイルを見つける。WAV は音のデータを最後まで読み、MP3 は先頭の形と大きさを見たうえで、MPEG のフレームをファイルの終わりまでたどって、最後のフレームの切れと、途中に挟まった MP3 でないデータ、ID3 タグのあとにフレームが無い（タグまでしか書けていない）ものを見つける）
  - **書き込み:** `cache/` など、放送が書き込む場所に書けるか。再生済みの記録を残せない（書けないと、再起動のたびに同じ回が鳴る）ものだけを NG にし、履歴や音声のキャッシュは警告にとどめる。状態ファイルが sticky ビットのフォルダ（`/tmp` など）にあり、フォルダも既存の `state.json` も別の利用者の持ち物のときも、置き換えて保存できないので NG にする
- **何も書かない**こと（ファイルもフォルダも作らず、権限も変えない）
- 結果は OK／情報／警告／NG で示し、NG には「直し方」を付けること。NG が 1 つでもあれば終了コード 1、警告と情報だけなら 0。設定ファイルを読めないときは、原因を日本語で示して終了コード 2
- 直し方に出す `chown` は、設定が指す場所そのものにしか使わないこと（実在する親の持ち主を変えさせない。まだ無い場所は、その 1 つだけを作って渡す）
- 導入スクリプト（`scripts/setup.sh`）の途中と CI でも実行すること。点検の結果が 2 のときだけ、導入スクリプトはサービスを再起動せず、「導入は途中です」と表示して終了コード 1 で終わる（`--no-service` を付けても同じ）

### FR-12 状態の確認（`--status`）と放送の履歴

- 現地で、次を一目で確かめられること（`python3 campus_chime.py --status`）: 版とコミット・時刻の同期・サービスの状態・再生方法・作り置きの音声・直近の放送・次の予定
- 鳴らさず、何も書かないこと。気になる点があれば、行末に印を付け、末尾に理由を並べ、終了コード 1 にすること。`timedatectl` や `systemctl` が使えない環境では「確認できません」と表示し、問題とは数えないこと
- 放送ごとの結果（成功・一部のみ・失敗・エラー、無音になった文言、音源ファイルが無くて鳴らせなかった部品）を、1 回の放送につき 1 行、`cache/history.jsonl` に残すこと。閉館アナウンスだけが鳴らなかった放送を「成功」と表示しないこと。組み立てに失敗して簡易の内容（時報音だけなど）で鳴らした放送も、結果が「成功」のまま見逃されないよう、行末に「簡易の内容で放送」と示し、直近の放送ならば気になる点に数えること。**書けなくても放送は止めない**こと。試し鳴らし（`--test-hourly` など）と `--dry-run` は残さない
- `--version` に、版とコミット（例: `campus-chime 6.1.0 (a1b2c3d)`）を表示し、起動時のログにも出すこと

### FR-13 更新（`scripts/update.sh`）

- 運用中の Pi を、1 つのコマンド（`bash scripts/update.sh`）で更新できること。最新版の取り込み・放送の時間帯の待機（`--wait-idle`。最大 360 秒）・導入スクリプトの再実行（点検とサービスの再起動を含む）・結果の表示（旧い版 → 新しい版と `--status`）までを行う
- 更新できない状態（root での実行、手元で Git 管理下のファイルを書き換えている、ブランチではなく特定のコミットを見ている、取り込めない）では、**何も変えずに**理由を表示して止まること（取り込みの失敗は、ネットワークの断・履歴の食い違いのほか、権限と、ディスクの問題（空き容量の不足・読み取り専用の SD カード・入出力エラー・容量の割り当て超過）と、Git 管理外のファイルの上書きを見分けて、それぞれの直し方を示す。権限またはディスクの問題で失敗したときは、取り込みが途中まで進んでいることがある）
- 放送の時間帯が終わらないときは、サービスを再起動せずに止まること（放送を途切れさせない）
- 取り込みのあとで止まっても（放送の時間帯が終わらない・`config.json` を読めない・導入スクリプトの失敗）、もう一度実行すれば続きから反映できること。サービスに反映した版を `cache/deployed_commit` に記録し、すでに最新版でも、記録がいまの版と合わなければ続きを行う（「すでに最新版です」で終わって、サービスが古い版のまま気づかれない、ということを避ける）
- 元の版へ戻す手順は表示するだけで、実行しないこと。表示するのは、コードを更新した回（取り込みのあとで止まった回を含む）だけで、続きから反映する回には表示しない
- `config.json` は上書きしないこと

### FR-14 休館日（`schedule.closures`）

- 設定ファイル（`config.json`）に書いた日は、**時報も閉館放送も鳴らさない**こと。1 日ずつ（`dates`）と、期間（`ranges`。両端を含む）の両方で書けること。名前（`name`）を添えられ、`--schedule` と `--status` に出ること
- **祝日は自動では休まない**こと（FR-05）。休む祝日は、その日を書く
- **書き方の正しくない項目は、その項目だけ無視して鳴らす**こと（日付の形が違う、`from` が `to` より後、など）。放送が止まる側には倒れない。ほかの項目は有効のままにする。無視した項目は ERROR ログに残し、`--check` が警告として直し方を示す
- 年末年始のような長い休みをまたいでも、休み明けの最初の予定を見つけられること（予定の探索は 400 日先まで）
- 休館日を書かなければ、放送の時刻と内容は今までと同じであること
- 現地で、休館日が分かること: `--schedule` が「休館 日付（曜日） 名前」の行を挟み、`--status` が今日から 14 日以内の休館日を挙げる

### FR-15 放送の一時休止（`--pause-today` / `--pause-until` / `--pause-off`）

- 現地で、コマンド 1 つで、今日だけ、またはある日まで（今日を含めて**最長 31 日**）、時報と閉館放送を止められること。サービスは止めず、**再起動も要らない**（常駐中のサービスが記録の書き換えを見て、予定を選び直す）。それより長い休みは、休館日（FR-14）に書く
- 実行したときに、何を止めるか（時報と閉館放送の回数。休館日と、今日はすでに鳴らした分を除く）と、いつ再開するかを表示すること。`--reason` で理由を添えられ、`--status`・`--schedule`に出ること（準備に入っていた回を止めたときは履歴にも付く）。`--pause-off` で早く戻せ、期限（終了日）が来れば自然に戻ること
- 止めた回は鳴らさず、**再生済みの記録を付けない**こと（止めた直後に解除すれば、追いかけ再生の猶予内の回は鳴る。`--pause-off` は、その回を表示する）。準備に入っていた回（再生開始の 45 秒前から）を止めたときは、履歴に「止めていた」と残すこと。先に止めた日の回は、予定の選び直しで外すだけとし、履歴には残さない（止めた期間と理由は `--status` の「放送の休止」で分かること）
- **失敗は鳴らす側に倒す**こと。休止の記録が無い・読めない・壊れている・知らない版・期限切れ、確かめる処理の例外は、すべて「止めていない」ものとして鳴らす。時報の「ポーン」を遅らせないこと（正時直前の最終調整のあいだは確かめない）。壊れた記録は WARNING で知らせ、`--check` が警告する
- root では実行できないこと（`cache/` が root の持ち物になり、サービスが記録を書けなくなるため）。引数の誤りは、設定を読む前に断ること
- 止めていること自体は、`--status` の「要確認」にしないこと（利用者の意思のため）。止めたつもりの記録が使えないとき（壊れている・読めない）は、`--status` の「放送の休止」が `--check` を案内すること（放送は通常どおり鳴るので、「要確認」にはしない）
- 書けない・消せないときは、終了コード 1 で次の手がかりを示すこと（記録の場所がフォルダなら、手で移すか消す。それ以外は `--check`）

### FR-16 音量（`audio.volume`）

- 時報音・読み上げ・蛍の光の音量を、別々に 0.0〜1.0 で設定できること。既定はどれも 1.0（今までの音量）
- **OS（ALSA）の音量は高めに固定し、アプリ側で絞る**運用とする
- 音量の設定の誤り（数でない、範囲外）で放送を止めないこと。数でなければ 1.0、範囲外は 0〜1 に丸める。`--check` が警告する
- 外部コマンド（`aplay` / `mpg123`）で再生する方式では、アプリは音量を変えられない（その旨を警告し、そのままの音量で鳴らす）

### FR-17 再生の停止と打ち切り

- 停止要求（`systemctl stop` / `restart`）に、待機中も**再生中も**応じ、再生中の音は 1 秒ほどで止まること（フェードアウトする）。音を出し始めていた回は再生済みとして記録し（鳴り直さない）、履歴に「中断」と残し、直近の放送なら `--status` が気になる点にすること。音を出す前に止まった回は、何も鳴っていないので、再生済みの記録も履歴も付けず、再起動のあと追いかけ再生の猶予内に鳴らし直せること
- systemd のユニットの `TimeoutStopSec` は 30 秒とし、止まらなかったときの保険にすること（以前は既定の 90 秒を待った）
- 1 つの音源が鳴り終わらなくても、上限の秒数で打ち切ること（WAV は音の長さ ＋ 10 秒、ほかは `audio.max_segment_seconds`）。放送の処理が戻らなくならないこと
- 音声デバイスの初期化に失敗したときは、3 回までやり直すこと（起動直後などでデバイスがまだ使えないことがあるため）

## 6. 非機能要件（Non-Functional Requirements）

### NFR-01 音声品質

- **再生中に音飛び・カクつき・途切れが発生しないこと**
- mixer のバッファサイズを明示的に指定し、既定値に依存しない実装とする（v1.x の主要不具合への対策）

### NFR-02 CPU 負荷

- 待機中の CPU 使用率を **1% 未満**に抑えること
- 1 秒ごとのポーリングではなく、次のイベント時刻まで待つ方式とすること

### NFR-03 自動復旧

- systemd により、電源投入後に自動的にサービスが開始されること
- 異常終了時は自動的に再起動されること
- 天気取得・音声合成・再生の失敗でプロセス全体を落とさないこと
- 放送の組み立て中の想定外のエラー（通信の途中切断、読み上げ文のテンプレートの書き間違いなど）でも、**時報音は鳴る**こと
- 設定値の書き間違い（範囲外・型違いなど）で、起動に失敗したり再起動を繰り返したりしないこと。ランタイムが動けない項目だけ、起動時に既定値へ置き換えて動かす。動ける値は置き換えない（FR-11）
- 停止要求（`systemctl stop` / `restart`）には、待機中も再生中も 1 秒ほどで応じること（FR-17）
- 休館日・休止・音量の設定や記録が壊れていても、起動に失敗せず、放送を止めないこと。使えない項目だけを無視し、鳴らす側に倒す（FR-14〜16）
- 起動時の確認（VOICEVOX ENGINE への疎通確認、作り置きの音声の数え上げ）が例外になったり、設定の値で際限なく手間がかかったりしても、起動を止めない（警告を残して続ける）

### NFR-04 時刻正確性

- 本機は RTC 非搭載のため、起動直後に NTP で時刻が大きく補正されても、**補正後の時刻で放送する**こと
- OS のタイムゾーンは `Asia/Tokyo` に設定されていること
- 時報の長音開始と正時のずれを **±100ms 以内**に抑えること
- NTP による時刻補正が待機中に入っても追従できること

### NFR-05 ログ

- 動作ログは systemd journal（`journalctl`）から参照できること
- 起動・予定・トリガー・再生開始／完了・再生内容（読み上げ文言）・エラーを記録すること
- 起動時のログに、版とコミット、作り置きの音声の件数を残すこと。足りなければ WARNING、設定の誤り（既定値に置き換えて続行）は ERROR で残すこと
- systemd 配下では重大度が付き、`journalctl -p err`（警告も見るなら `-p warning`）で絞り込めること（v5.3.0 から。それ以前は常に空だった）
- タイムスタンプは設定されたタイムゾーンで表示されること

### NFR-06 ネットワーク

- 接続は 2.4GHz 帯の Wi-Fi とする
- **時報音・時刻アナウンス・閉館放送はネットワークに依存しない**こと
- 天気予報のみネットワークを使う。取得失敗時も放送は継続されること
- 天気 API の呼び出しは 1 時間に 1 回以内に抑えること（キャッシュ）

### NFR-07 保守性

- 主要ロジックにユニットテストがあり、**ネットワーク・音声デバイスなしで実行できる**こと
- CI（GitHub Actions）でテストが自動実行されること
- 設定の既定値と `config.example.json` の乖離を自動検出できること
- シェルスクリプト（`scripts/*.sh` のすべて）を、CI で 1 本ずつ構文チェック（`bash -n`。複数のファイルを渡しても 1 つ目しか調べないため）と shellcheck にかけること
- 設置状態の点検（`--check`）が、リポジトリに入っているものだけで通ることを CI で確かめること
- 文書に書いた件数・コマンド・節の参照が、実装と食い違わないことを自動テストで確かめること

### NFR-08 安全性（点検と強化）

- 安全面の点検（`scripts/security_check.sh`）は、**何も書かず、何も変えない**こと。Pi のアドレスがプライベートかグローバルかを見分け、グローバルなら、学外から届くかを確かめる方法とあわせて知らせること。直し方（`harden.sh` の手順）を添えること
- 強化（`scripts/harden.sh`）は、手順ごとに選べて、**変える前にすべての条件を確かめ、変えたあとに確かめ、確かめられなければ自分で戻す**こと。変える前のファイルを控え、`--rollback` で内容と権限まで戻せること
- SSH と防火壁のように、締め出される恐れのある変更は、**新しい端末で入り直せることを確かめて確定するまで、一定の時間で自動で元に戻す**こと（再起動しても戻す）
- 強化によって、放送の時刻と内容を変えないこと。放送を止めうる手順は、放送の終わりを待ってから行うこと
- 点検と強化のスクリプトを、実機に触れずに（偽のシステムと偽のコマンドで）自動テストで確かめること
- 運用者向けの手引き（`docs/SECURITY.md`）に、進める順、手順ごとの放送への影響と元に戻し方、締め出されたときの復旧、毎月の点検、GitHub 側の守り、脆弱性の報告の窓口を書くこと。手引きは、攻撃のやり方ではなく、守り方を書くこと（リポジトリは公開）

## 7. 制約・前提条件

- 本機はチャイム専用機とし、他用途のプロセスを常駐させない
- SD カードは現行カードを上書きし、旧環境のデータは引き継がない
- 実行ユーザー名は `pi` とする（systemd ユニットが `/home/pi` 前提のため）
- 閉館放送用の音源ファイルはリポジトリに同梱し、実行時に外部取得を行わない
- 時報音は実行時に合成し、リポジトリには含めない

## 8. 著作権・ライセンス規定

- **楽曲:** パブリックドメインまたは著作権フリー音源を使用すること（Auld Lang Syne = Public Domain）
- **合成音声:** VOICEVOX:ずんだもん。事前生成して同梱するほか、任意で VOICEVOX ENGINE により実行時にも合成する。クレジット表記に対応した利用条件で使用する
- **天気予報:** Open-Meteo（CC BY 4.0）。出典を README に明記する
- **時報音:** 本リポジトリのコードによる合成音であり、第三者の権利を含まない

## 9. 受け入れ条件（Acceptance Criteria）

| # | 条件 |
|---|---|
| A-01 | 平日 10:00〜16:00 の毎正時に時報が鳴り、長音の開始が正時と一致している |
| A-02 | 時報のあとに時刻が読み上げられ、12:00 は「正午」と読まれる |
| A-03 | 時報のあとに「ひとこと」が流れ、同じひとことが連続しない。12 時はその前に天気予報も流れる |
| A-04 | ネットワークを切断しても時報と閉館放送が鳴る |
| A-05 | 平日 16:57 にアナウンス → 蛍の光（フェードイン）が鳴る |
| A-06 | 土日は一切鳴らない |
| A-07 | 電源再投入後、自動的にサービスが起動する |
| A-08 | 再生中に音飛び・カクつきがない |
| A-09 | 待機中の CPU 使用率が 1% 未満である |
| A-10 | `config.json` の変更（文言・地点を変えたときは、Pi の `config.json` を PC に持ってきて `--config` で渡す読み上げ音声の作り直しを含む）だけで、時刻・地域・文言を変更できる |
| A-11 | `python3 -m unittest discover -s tests -t .` が全て成功する |
| A-12 | 導入直後の Pi で `python3 campus_chime.py --check` を実行すると、NG が無い（終了コード 0）。何も書き込まれない |
| A-13 | 稼働中の Pi で `python3 campus_chime.py --status` を実行すると、末尾が「気になる点は見つかりませんでした。」で、「自動起動」が「有効」になっている |
| A-14 | 放送のあと、`--status` の「直近の放送」にその回の結果が残る。履歴を書けない状態でも、放送は鳴る |
| A-15 | `bash scripts/update.sh` で更新でき、放送の時間帯なら終わるまで待ってから再起動する。更新できない状態では、何も変えずに理由を表示して止まる。取り込みのあとで止まったときは、直してもう一度実行すれば続きから反映される |
| A-16 | 設定に書いた休館日は、時報も閉館放送も鳴らず、`--schedule` に「休館 …」の行で出る。書いていない祝日（平日）は鳴る。休館日の書き間違いは、その項目だけが無視され、`--check` が警告する |
| A-17 | `--pause-today` で今日の残りの放送が止まり（再起動は要らない）、`--pause-off` または終了日の翌日に戻る。`--status` の「放送の休止」に出る。休止の記録を壊しても、放送は鳴る |
| A-18 | `audio.volume` で、時報音・読み上げ・蛍の光の音量を別々に絞れる。既定では今までと同じ音量で鳴る |
| A-19 | 再生中にサービスを停止すると、音が 1 秒ほどで止まる（30 秒待たされない）。その回は `--status` の「直近の放送」に「中断」と残る |
| A-20 | `bash scripts/security_check.sh` は何も書かず、何も変えない（`[要対応]` が無ければ終了コード 0）。`sudo bash scripts/harden.sh` の各手順は、条件を満たさなければ何も変えずに止まり、`--rollback` で元に戻せる。`ssh`・`firewall` は、新しい端末で `--confirm` しなければ、時間が来たところで自動で元に戻る。どの手順の後も、放送の時刻と内容は変わらない |
